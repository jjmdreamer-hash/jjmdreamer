# OMR 채점기 인수인계 문서

다른 AI(ChatGPT 등)나 개발자가 이어서 작업할 수 있도록 지금까지 만든 내용을 정리한 문서입니다.
이 문서와 `docs/omr/index.html` 파일을 함께 첨부해서 대화를 시작하세요.

---

## 1. 무엇을 만들었나

객관식 시험용 **OMR 채점 웹앱**입니다. 선생님이 쓰는 도구입니다.

1. 시험 설정: 문항 수(1~75), 보기 수(4지·5지), 문항별 배점, 정답을 입력합니다.
2. 답안지 출력: 이 앱 전용 A4 OMR 답안지를 인쇄합니다.
3. 채점: 학생이 마킹한 답안지를 휴대폰으로 찍거나 사진을 올리면, 자동으로 읽어서 점수를 보여줍니다.
4. 결과: 학생별 점수, 평균·최고·최저, 문항별 정답률을 보고 엑셀로 내보냅니다.

- 서버, AI, 외부 라이브러리 없이 **HTML 파일 하나**로 동작합니다. 이미지 처리도 모두 브라우저 안에서 직접 구현했습니다.
- 사진은 기기 밖으로 전송되지 않습니다.

## 3. 화면 구성

탭 3개로 나뉘어 있습니다.

- **① 시험 설정**
  - 시험 선택 / 새 시험 / 삭제
  - 시험 이름, 문항 수, 보기 수
  - 답안지 출력하기: `window.print()`로 인쇄합니다. 링크 안에서는 막혀서 숨깁니다.
  - 답안지 이미지 만들기: 2480×3508px(A4 300dpi) PNG로 보여주고, 사용자가 저장해서 인쇄합니다.
  - 정답 빠른 입력(`31425…`), 모든 문항 배점 일괄 적용, 100점 맞추기(0.5점 단위로 나눔)
  - 정답 마킹한 답안지를 찍어서 정답 등록
  - 문항별 정답 버튼과 배점 입력
- **② 채점**
  - 카메라로 찍기: `<input type="file" accept="image/*" capture="environment">`
  - 사진 여러 장 올리기: `multiple`
  - 결과 카드: 점수, 맞은 수, 학번·이름 입력, 사진 위 표시, 문항별 O/X와 답 수정
  - 사진 위 표시: 초록 = 맞음, 빨강 = 틀림, 파란 점선 = 정답, 주황 = 확인 필요
- **③ 결과**
  - 응시 인원, 평균, 최고, 최저
  - 학생별 점수표
  - 문항별 정답률 막대. 50% 미만은 빨간색입니다.
  - CSV 다운로드(링크 안에서는 숨김), 엑셀 붙여넣기용 복사(탭으로 구분)

## 4. 답안지 배치 (좌표 단위 mm, A4 210×297)

코드에 있는 `buildLayout()`과 `sheetSVG()`가 같은 좌표를 씁니다. **인식은 이 좌표에 의존하므로, 바꾸면 이미 출력한 답안지는 못 읽습니다.**

- **모서리 기준 사각형**: 한 변 8mm 검은 정사각형 4개. 중심 좌표는 (14,14), (196,14), (196,283), (14,283)입니다.
- **방향 표시**: 한 변 4mm 정사각형. 중심은 (25,14)로 좌상단 옆에 있으며, 사진이 돌아가 있어도 위아래를 판별하는 데 씁니다.
- **종이 밝기 측정점**: (105,14), (14,148), (196,148), (105,283). 이 위치는 비워 둬야 합니다.
- **학번**: 2자리(십의 자리, 일의 자리). 각 자리는 0~9 버블 10개입니다.
  - 버블 위치는 y=38과 y=47, x=112+d×7.5입니다.
- **문항**
  - 한 열에 최대 25문항이고, 열 수는 `ceil(n/25)`입니다(최대 3열, 75문항).
  - 행 간격 8mm, 보기 간격 7mm, 버블 반지름 2.6mm입니다. 시작 y는 66mm입니다.
- 모서리 근처의 가장자리 선 위(y=14 줄, x=14 줄 등)에는 아무것도 인쇄하면 안 됩니다. 방향 판별이 틀어집니다.

## 5. 인식 알고리즘 (`analyze()`)

1. 사진을 긴 변 1400px로 줄이고 흑백으로 바꿉니다(`fileToCanvas`, `canvasToGray`).
2. **적응형 이진화**를 합니다(`findBlobs`).
   - 적분 영상으로 주변 평균을 구합니다. 창 반지름은 긴 변의 1/20입니다.
   - 주변 평균의 72%보다 어두운 픽셀을 검정으로 봅니다.
3. **연결 요소**를 찾고, 크기·가로세로비(0.5~2)·채움률(>0.45)로 사각형 후보를 거릅니다.
4. 면적이 큰 후보 18개로 **4개 조합을 전부** 검사합니다(`locateSheet`).
   - 볼록한 사각형인지 확인합니다.
   - 네 블롭의 크기 차이가 3배 이내여야 합니다.
   - 긴 변과 짧은 변의 비가 1.1~2.3이어야 합니다.
   - 마커 크기와 짧은 변의 비가 0.02~0.09여야 합니다.
   - 조건을 통과한 사각형 중 넓은 순으로 시도합니다.
5. 네 점을 각도순으로 정렬하고 회전 4가지 각각에 대해 **호모그래피**(mm→픽셀)를 구합니다.
   - 방향 표시 위치가 가장 검은 회전을 고릅니다.
   - 방향 표시 채움 > 0.55, 반대쪽 빈칸 < 0.3이어야 통과입니다.
6. 기준 밝기를 정합니다.
   - 검정 = 마커 안쪽 평균, 종이 = 측정점 4곳 중 가운데 두 값의 평균입니다.
   - 버블마다 반지름 1.7mm 안을 샘플링해서 `채움 = (종이 − 값) / (종이 − 검정)`을 구합니다.
7. 판정(`readGroup`)
   - 채움 0.45 이상인 보기가 1개면 그 답입니다.
   - 2개 이상이면 가장 진한 것이 다음 것보다 0.3 이상 진할 때 그 답이고(지운 자국 처리), 아니면 `multi`(두 개 이상 칠함, 확인 필요)입니다.
   - 0.45 이상은 없고 0.22 이상이 있으면 가장 진한 것을 답으로 하되 `faint`(흐림, 확인 필요)로 표시합니다.
   - 둘 다 아니면 `blank`(안 칠함)입니다.

## 6. 데이터 저장

`localStorage`의 키 `omr-grader-v1`에 JSON으로 저장합니다. 그 브라우저에만 남고, 다른 기기와는 공유되지 않습니다.

```js
{
  exams: [{ id, title, n, choices, key: [정답 1~choices 또는 null], pts: [배점] }],
  cur: "현재 시험 id",
  results: {
    "<examId>": [{ id, sid: "학번", idOk, name, answers: [{ v: 답 또는 null, st: "ok|multi|faint|blank", fixed? }], at }]
  }
}
```

- 점수는 저장하지 않고 화면에 보일 때마다 `grade()`로 다시 계산합니다. 그래서 나중에 정답이나 배점을 고쳐도 자동으로 반영됩니다.
- 같은 시험에서 같은 학번을 다시 채점하면 이전 결과를 바꿉니다(`dedupe`).
- 사진은 저장하지 않습니다. 사진 위 표시는 채점 직후에만 보입니다.

## 7. 링크(Claude 아티팩트) 안에서의 제약과 대응

| 막힌 기능 | 대응 |
|---|---|
| `window.print()` | 링크 안에서는 버튼을 숨기고 "답안지 이미지 만들기"로 대신합니다 |
| 파일 다운로드(CSV) | 버튼을 숨기고 클립보드 복사로 대신합니다. 복사가 실패하면 텍스트를 선택한 상태로 보여줍니다 |
| `alert`, `confirm` | 페이지 안 대화상자 `ask()`, `notice()`로 바꿨습니다 |

링크 안인지는 `window.self !== window.top`으로 판별합니다. GitHub Pages 같은 일반 주소에서는 인쇄와 CSV가 그대로 보입니다.

## 8. 시험해 본 것

- **인식 테스트**: Playwright와 Chromium으로 가상 사진 6장을 만들어 확인했습니다.
  - 20·25·30·50·75문항, 4지·5지 조합입니다.
  - 원근 왜곡, 90°·180°·270° 회전, 조명 차이, 노이즈, 연하게 칠한 칸, 두 개 칠한 칸, 지운 자국을 넣었습니다.
  - 학번과 모든 문항을 정확히 읽었습니다. 한 장에 0.1~0.2초 걸렸습니다.
- **화면 흐름 테스트**: 모바일 크기에서 정답 입력, 사진 올리기, 점수 표시, 확인 필요 표시를 확인했고, 예상한 대로 동작했습니다.
- **아직 안 해 본 것**: 실제로 출력한 종이와 실제 휴대폰 카메라 사진. 첫 실제 사용 때 인식률을 꼭 확인하세요. 문제가 생기면 5번의 임계값(0.72, 0.45, 0.22)부터 조정하면 됩니다.

## 9. 알려진 한계

- 이 앱에서 출력한 답안지만 읽을 수 있습니다. 시중 OMR 카드는 못 읽습니다.
- 답안지에는 어떤 시험용인지 정보가 없습니다. 채점할 때 화면에서 선택한 시험의 배치로 읽으므로, 문항 수가 다른 답안지를 찍으면 엉뚱하게 읽힙니다.
- 학번은 2자리(00~99)까지만 됩니다. 반, 번호 같은 구분은 없습니다.
- 데이터가 브라우저에만 있어서, 기기를 바꾸거나 브라우저 데이터를 지우면 사라집니다.

## 10. 다음에 할 일 (논의 중이던 것)

**회원가입·로그인**을 추가하려고 했습니다. 아직 방식을 정하지 않았습니다.

- **A. 혼자 또는 아는 사람 몇 명만 쓴다면**: Claude 아티팩트의 "보는 사람 확인"과 "공유 데이터 저장" 기능으로 Claude 계정을 로그인처럼 쓰는 방법이 있습니다. 이 방법은 Claude 안에서만 가능합니다.
- **B. 누구나 가입하는 서비스로 만든다면**
  - Supabase나 Firebase로 이메일 회원가입·로그인을 만들고, 시험·결과를 서버 DB에 저장합니다.
  - 앱은 GitHub Pages, Netlify, Vercel 같은 일반 주소에 올립니다.
  - 해야 할 일: 서비스 계정 만들기 → `exams`/`results` 테이블 설계(6번 구조 참고) → localStorage 읽기·쓰기를 DB 호출로 바꾸기 → 사용자별로 자기 데이터만 보이게 행 단위 보안(RLS) 설정.
  - ChatGPT에서 이어서 한다면 B가 현실적입니다.

그 밖에 고려할 만한 것:

- 답안지에 시험 코드를 마킹 칸으로 넣어서 시험을 자동으로 구분하기
- 학번 자릿수 늘리기, 반 선택 칸 추가
- 결과를 엑셀 파일(.xlsx)로 내보내기
